## 1. 本轮三处修复与验证

1. **RevealField busy 卡死**：catch 分支里 `clear()` 先递增 `reqSeq`，`finally` 的 `seq === reqSeq.current` 守卫此后恒不成立，`setBusy(false)` 被跳过。修复是在进入 catch 后、调用 clear() 前就地复位 busy。回归测试 `revealField.test.tsx`「reveal 失败后按钮必须可重试」做了双向验证：打回原代码该测试变红（1 failed），恢复修复后 3 个套件 41 条全绿。
2. **session.ts lock() 竞态**：`get().status ? { ...get().status! }` 二次 get 之间若被 markLocked 插入 set，展开的是旧快照。改为与 markLocked 一致的单次 `const cur = get().status`。
3. **导入错误文案**：原句「请到『导入导出』页看完整清单」指向已整页移除的功能（该文件 :58-59 注释自证），且弹窗本身只渲染前 5 条、无任何完整清单入口——按「界面文案必须兑现成代码做得到的事」改为「修正文件后重新选择可刷新此清单」。既有反向断言（:313 断言不得出现「请到『导入导出』页」）继续通过。

## 2. 后端安全偏离项（均为已签字，非失误）

- **DB 主密钥默认放本机 0600 文件**（`lib.rs:41-45`、`secfile.rs`）而非钥匙串：ad-hoc 签名下钥匙串 ACL 每重打包必弹授权框，2026-10-17 起改道，有同意闸门与文档（《密钥生命周期与加密边界》§4.7）。代价：同用户进程可读该文件，弱于 §7.2 要求——回退到安全存储需同时把 Developer ID 签名写进装机基线。
- **导出/复制免二次认证出厂关闭**（迁移 0007/0008）：交付方 2026-10-18/19 点名；后端 `gate_export_reauth` 逻辑完整保留，测试 `export_gate_follows_the_policy_setting` 钉住语义。
- **主密码以明文 String 过 IPC**（`commands/vault.rs`）：Tauri serde 边界固有局限，无法在反序列化侧清零；窗口内已有 CSP 与能力最小化兜底。

## 3. 三端支持矩阵

| 维度 | macOS | Windows | Linux |
|---|---|---|---|
| 代码平台分支 | `fill_host.rs` / `keystore.rs` / `shortcut.rs` / `lan/discovery.rs` 均有 `cfg` 分支，无平台被功能阉割 | 同左；注册表项故意留给用户（`fill_host.rs:97-99`） | 同左；keyring 走 secret-service，默认路径不使用故无硬依赖 |
| 图标 | `icon.icns` ✅ | `icon.ico` ✅ | PNG 集 ✅ |
| bundle.targets | dmg, app | nsis, msi | deb, rpm, appimage（配置已全列） |
| 侧车 `mda_fill_host` | ✅ 已有 aarch64-apple-darwin | ❌ 需 windows-msvc 二进制 | ❌ 需 linux-gnu 二进制 |
| 本机（macOS arm64）可产出 | ✅ | ❌（.msi/.exe 必须在 Windows 上打包；本机无 cargo-xwin/docker） | ❌（无 Docker 与 Linux 工具链） |
| 产出通道 | 本机 `npx tauri build --bundles app,dmg` | GitHub Actions `windows-latest`（原生 msvc，无需交叉） | GitHub Actions `ubuntu-22.04`（需 apt 装 webkit2gtk-4.1 等） |

**本轮已交付**：`.github/workflows/release.yml` —— 三系统矩阵，每个 runner 在自己的 OS 上跑 `prepare-host-binary.sh` 产出对应 triple 的侧车（externalBin 阻塞由此解开），先 `npm run verify` + `cargo test` 门禁再 `tauri build`，按平台上传 dmg/app、nsis+msi、deb+rpm+appimage（rpm 缺 rpmbuild 时降级不阻塞），附 SHA-256 摘要清单。**前提**：本仓库尚无 git 远程，需创建 GitHub 仓库推送后打 `v*` tag 或手动 dispatch 触发；这是未经本机验证的路线，产物仍按《部署手册》§1.2 要求在目标平台各跑一次安装与首启。

**发布前已知注意项**（记录，不改配置）：
- 三端产物均未签名：macOS Gatekeeper 拦、Windows SmartScreen 拦；可信分发需组织证书签名+公证（《部署手册》§1.3）。
- `windows.webviewInstallMode: downloadBootstrapper`：内网无外网时安装阶段会失败，需评估改 `embedBootstrapper` 或预置 WebView2 运行库（《部署手册》§1.2 未验证项）。
- Linux 各发行版 AppImage 运行时 FUSE 兼容性、deb/rpm 依赖声明需在目标机上实测。
