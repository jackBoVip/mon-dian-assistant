# 蒙电信产助手 · 浏览器扩展（安全填充）

配合桌面应用「蒙电信产助手」使用的一次性凭据填充扩展（Manifest V3）。
扩展本身**不保存任何账号、口令或票据**：凭据只在桌面应用签发的
一次性票据（约 60 秒有效、绑定站点 Origin 与当前会话）被兑换成功的瞬间，
经本机宿主进程一次性下发给页面脚本填入表单，**永不自动提交**。

## 一、加载扩展（开发者模式「加载已解压的扩展程序」）

以下路径均指本仓库的 `extension/` 目录。

### Chrome

- macOS：打开 `chrome://extensions/` → 右上角开启「开发者模式」→
  点击「加载已解压的扩展程序」→ 选择 `extension/` 目录。
- Windows：同上（地址栏输入 `chrome://extensions`）。
- Linux：同上。

### Edge

- macOS / Windows / Linux：打开 `edge://extensions/` → 左下角或右上角开启
  「开发者模式」→ 点击「加载解压缩的扩展」→ 选择 `extension/` 目录。

> 其他基于 Chromium 的浏览器（如 Chromium 本体、Brave）加载方式与 Chrome 相同。

## 二、查看并登记扩展 ID

1. 加载成功后，在扩展管理页每张卡片上会显示一串 **32 位小写字母（a–p）**
   组成的 ID，例如 `abcdefghijklmnopabcdefghijklmnop`。
   也可以打开扩展的状态弹窗，页面底部直接显示「本扩展 ID」。
2. 把这串 ID 填入桌面应用：**系统管理 → 浏览器扩展**。
3. 桌面应用会用这串 ID 生成宿主清单 `com.mda.fillhost.json`
   （`allowed_origins` 精确到 `chrome-extension://<ID>/`），
   并写入各浏览器的 `NativeMessagingHosts` 目录。
   **未登记 ID 之前，宿主清单不会生成，浏览器也无法发现宿主。**
4. 清单写入后需**重启浏览器**，扩展才能发现宿主。
5. Windows 特别说明：Chrome/Edge 通过注册表定位清单，桌面应用只生成清单文件
   并在界面上给出注册表键位置（`HKCU\Software\Google\Chrome\NativeMessagingHosts\com.mda.fillhost`），
   需要你自行确认后将该键指向清单文件路径；应用不会自动改注册表。
6. 重新加载扩展（改动代码后点扩展卡片上的「刷新」）可能不会改变 ID，
   但**删除后再加载会换一个 ID**，此时需回到桌面应用更新 ID 并重新安装清单。

## 三、日常使用流程

1. 打开桌面应用并解锁会话（锁定时扩展只会显示「已连接（已锁定）」，拿不到任何凭据）。
2. 在桌面应用的台账/快捷启动器中，对目标账号点击 **「打开并安全填充」**。
   桌面应用随后才会签发一次性票据，并用系统浏览器打开登录地址。
3. 扩展在打开的 https 页面上自动核对页面 Origin 与票据绑定：
   - 匹配且该凭据未开启「每次填充前确认」→ 直接填入用户名和口令；
   - 匹配且开启了确认 → 页面弹出「填充确认」面板，按「确认填充」才填入，
     按「取消」或 **Esc** 放弃（票据随之作废）。
4. 填充完成后表单**不会被提交**，需要你自行核对并登录。
5. 每张票据只能兑换一次、约 60 秒过期、绑定 Origin + 用户 + 应用会话；
   第二次用同一票据请求会被桌面应用拒绝（`TICKET_INVALID`）。

扩展状态弹窗中的「重新检测」按钮会重走一次 hello 检测，
并在当前标签页为 https 时触发该页面重新核对是否有待消费的票据。

## 四、安全模型（如实说明）

- **通道构成**：扩展 ←(Chrome Native Messaging, stdio 长度前缀帧)→ 宿主进程
  `mda_fill_host` ←(127.0.0.1 随机端口 TCP + 一次性令牌)→ 桌面应用。
  通道文件 `host-channel.json` 权限 0600，令牌随应用重启更换，
  应用退出/锁定时清理。
- **宿主不持密钥**：宿主进程只做转发，不落盘、不缓存任何凭据。
- **扩展不缓存秘密**：票据、用户名、口令只存在于单次请求的内存变量中，
  用完即清；`chrome.storage` 里只有连接状态和时间戳这类非秘密信息。
  凭据不写入 DOM 属性、localStorage/sessionStorage，也不打印到 console。
- **Origin 精确匹配**：桌面端只认台账中明确绑定的精确 https Origin；
  内容脚本仅注入 `https://*/*`，http 页面不参与填充。
- **已知边界（不粉饰）**：
  - 回环通道令牌文件对**同一用户**可读。同机同用户下的恶意软件若能读到
    令牌文件并拉起宿主，理论上可伪造请求。这正是票据被设计为
    **一次性、约 60 秒短时效、并绑定 Origin/用户/会话**的原因——
    伪造者也只能在你已经点击「打开并安全填充」且恰好知道目标 Origin 的
    极短窗口内命中一次。请锁好你的会话（离开即锁定），不要把令牌文件
    复制到共享目录。
  - 页面内脚本（第三方 JS）无法从扩展处读取凭据：填充走原生 value setter
    与事件派发，不经过任何全局变量或 DOM 属性；但它能观察到输入框内容的
    变化，因此请只在台账绑定的可信站点使用该功能。
- **MV3 的诚实限制**：Manifest V3 的 service worker 会被浏览器随时回收，
  「常驻 Native Messaging 端口」无法真正保证。本扩展的落地方案是
  **按需连接**：端口断开或超时即明确返回 `APP_NOT_RUNNING` / `TIMEOUT`，
  下一次请求自动重新拉起宿主；不存在假装已连接或返回旧缓存的行为。

## 五、文件清单

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | MV3 清单；权限仅 `nativeMessaging` / `storage` / `activeTab` / `scripting` |
| `background.js` | service worker：唯一的宿主端口通道，三个协议调用 hello / challenge / fill |
| `content.js` | 页面内：找输入框、React 受控组件兼容填充、确认面板、绝不提交 |
| `popup.html` / `popup.js` | 状态弹窗：未连接 / 已连接（已锁定） / 已连接（可填充）+ 重新检测 |

无构建步骤、无第三方依赖；目录本身即扩展源码，直接「加载已解压的扩展程序」。
